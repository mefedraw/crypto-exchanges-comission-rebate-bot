# Bybit: точная комиссия по uid за произвольный период

**Дата:** 2026-07-10
**Статус:** утверждён

## Проблема

Текущий адаптер Bybit ([bot/exchanges/bybit.py](../../../bot/exchanges/bybit.py)) ходит в
`GET /v5/user/aff-customer-info`, который отдаёт только **скользящие** окна 30/365 дней и
не умеет произвольный `[date_from, date_to]`. Поэтому `supports_date_range = False`, и бот
показывает дисклеймер «только скользящее окно», а не сумму за запрошенный период.

Живая проверка (см. probes в scratchpad) подтвердила: `GET /v5/affiliate/aff-user-list`
с параметрами `startDate`/`endDate` возвращает поле `commissionsVol` — комиссию именно за
этот интервал, отдельно от 30/365-дневных окон.

## Решение

Полностью **заменить** эндпоинт на `/v5/affiliate/aff-user-list`. Rolling-режим удаляется.

### Поток `get_commission(uid, date_from, date_to)`

1. Формируем `startDate`/`endDate` как `YYYY-MM-DD` из `date_from`/`date_to`. Bybit принимает
   календарные даты (не таймстемпы), поэтому нарезка `iter_windows` не нужна — весь диапазон
   уходит одним набором запросов. Период уже ограничен 365 днями в `validate_period`.
2. Листаем список: `size=100`, `startDate`, `endDate`, переход по `nextPageCursor`.
   Server-side фильтра по uid у эндпоинта **нет** — ищем нужный `userId` на стороне клиента.
3. Нашли `userId` → читаем `commissionsVol`, суммируем **только USDT** (требование владельца),
   прекращаем листание.
4. uid не встретился после всех страниц → пустой результат с заметкой
   «uid не найден в списке рефералов Bybit за этот период».
5. `supports_date_range = True`. Дисклеймер про скользящее окно убираем. `settlement_note`
   про accrued ≠ payout остаётся.

### Подпись и HTTP

Схема подписи Bybit v5 не меняется: `SIGN = hmac_sha256_hex(ts + apiKey + recvWindow + query)`.
Переиспользуется существующий `_headers` / `hmac_hex`. Постраничные запросы идут через
`BaseHttpAdapter._send` (ретраи/бэкофф/маскирование уже там).

### Компромисс

Отсутствие server-side фильтра по uid означает, что каждый запрос листает весь список
рефералов (по 100 на страницу). Для бота одного владельца приемлемо. Добавляем защитный
предел числа страниц и `log`-предупреждение при его достижении.

### Не входит в объём (YAGNI)

- `tradeVol` (объём торговли) — не показываем, результат строго про комиссию USDT.
- Другие монеты (`MNT`, `USDC`, ...) — как и раньше, игнорируются, при наличии ненулевых
  добавляется заметка.

## Тесты (httpx-mock, без живого API)

- uid найден на 1-й странице → сумма USDT из `commissionsVol`.
- uid найден на 2-й странице → корректная пагинация по `nextPageCursor`.
- uid не найден → пустой результат + заметка.
- `commissionsVol` с несколькими монетами → в результате только USDT + заметка про прочие.
- `supports_date_range is True`.
