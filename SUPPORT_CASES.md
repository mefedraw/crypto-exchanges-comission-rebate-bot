# Обращения Через Бота

## Пользователь

В личном кабинете всем видна одна кнопка «Техническая поддержка».
Внутри раздела: «Создать новое обращение» и «Мои обращения».
Создание: биржа из активных привязанных аккаунтов → UID → текст →
предпросмотр → явное нажатие «Отправить».

Предпросмотр показывает биржу, UID, контакт пользователя и текст в том же
формате, в котором обращение получат администраторы. До отправки текст можно
изменить. «Отмена» удаляет панель, не отправляя отдельного уведомления.

Доступ: не менее **100 USDT рефбека до сбора бота**, суммарно по пользователю
за всю учтенную историю. Включены подтвержденные начисления по всем UID,
в том числе уже выплаченные, истекшие и исторические корректировки.
Неподтвержденные строки не учитываются; для других активов используется
сохраненный USDT-эквивалент, а не сложение разных валют.

Порог ограничивает только создание нового обращения, а не открытие раздела
и не просмотр уже существующих обращений. Он проверяется повторно при сохранении.
Пользователь ниже порога видит
вежливое объяснение критерия и свою учтенную сумму. Вывод денег не лишает доступа.

Ограничения: 1200 символов в сообщении; до двух новых обращений за скользящие
24 часа суммарно по всем UID пользователя, включая уже закрытые обращения.
Проверка выполняется до оформления и повторно при сохранении под блокировкой
пользователя в БД. Повтор одного подтверждения не расходует лимит.
По-прежнему допускается до трех открытых одновременно и один открытый на UID. Дополнение
пользователем существующего кейса допускается раз в минуту. Черновик действует
30 минут; после перезапуска незавершенный черновик нужно создать заново.

## Администратор

Новые кейсы и дополнения поступают администраторам из `ADMIN_TELEGRAM_IDS`.
В админке есть раздел «Обращения» с вкладками «Активные» и «Закрытые».
Администратор может взять новое обращение в работу, ответить с предпросмотром
или закрыть кейс. Ответ хранится внутри обращения; пользователь получает
короткое уведомление с кнопкой «Открыть кейс». Обе стороны могут читать историю сообщений;
пользователь может дополнить или закрыть только свой кейс.

## Статусы

1. **Отправлено**: создано новое обращение. Уведомление получает администратор,
   пользователь видит подтверждение отправки в текущем экране.
2. **Открыт кейс**: администратор явно нажал «Взять в работу». Простой просмотр
   карточки статус не меняет и отдельного сообщения пользователю не отправляет.
3. **Требуется ответ**: администратор отправил сообщение пользователю. Приходит
   короткое уведомление с кнопкой открытия; сам запрос виден в карточке.
4. **Кейс закрыт**: переписка доступна только для чтения. Приходит короткое
   уведомление с кнопкой открытия. Закрывать может администратор или владелец кейса.

Ответ пользователя на запрос возвращает статус «Открыт кейс» и уведомляет
администраторов. Дополнение еще не принятого обращения сохраняет «Отправлено».
Повторное принятие или закрытие не дублирует смену статуса и уведомление.
Запоздалый запрос ответа не отправляется, если он уже отвечен, заменен более
новым сообщением поддержки или обращение закрыто к моменту проверки очередью.
Старые уведомления ответа поддержки совместимы с новым кратким форматом.

Карточка показывает статус, номер обращения, биржу, UID, контакт пользователя
и последнее сообщение; вся переписка доступна через «История сообщений».
В списке номер, биржа и статус помещены в отдельную строку-кнопку для каждого
обращения. UID остается в карточке, чтобы длинные значения не обрезали статус.

## Хранение И Безопасность

- `support_cases` хранит владельца, снимок биржи/UID, пороговую сумму и статус.
- `support_messages` хранит переписку и автора каждого сообщения.
- Создание, сообщения, аудит и очередь уведомлений сохраняются одной транзакцией.
- Повторное или одновременное подтверждение не создает дубль кейса/сообщения.
- Проверяются принадлежность UID, актуальный статус аккаунта и права на кейс.
- Пользовательский текст экранируется для HTML и не записывается в логи.
- Телеграм-сбой не удаляет кейс; очередь повторяет доставку. После исчерпания
  десяти попыток кейс остается доступен администратору в списке.
- Балансы, рефбек, комиссии и операции вывода не изменяются.

## Языки Пользовательского Интерфейса

Добавлены русский, английский, украинский, китайский упрощенный, турецкий,
хинди, тайский и вьетнамский. В главном меню есть выбор языка, также доступна
команда `/language`. Языки подписаны собственными названиями без флагов стран.

Новая регистрация использует `Telegram User.language_code`; региональные
суффиксы нормализуются, неподдерживаемый или отсутствующий язык дает английский.
Существующим пользователям миграция `b369c217f458` сохраняет русский.
Выбранный язык записывается в `users.locale`, проверяется allowlist и имеет
приоритет над языком Telegram. Он не хранится только в memory/FSM.

Языковой middleware не создает пользователей. При первом `/start` сначала
атомарно выполняется прежняя регистрация с обработкой рефссылки, затем язык
сохраняется в той же транзакции. Существующий пользователь не становится
рефералом после смены языка. Callback-коды, UID, ссылки и API-права не меняются.

Тексты переведены в меню, кошельке, UID, статистике, выводе, каталоге ссылок,
приглашениях, партнерской программе и поддержке. Уведомления о выплатах,
смене ранга и действиях по кейсу получают актуальный язык из БД при отправке.
Контекст языка изолирован по async-задаче. Админка и административная поддержка
остаются русскими; отмена обновления credentials не требует запроса языка в БД.
Исходный текст переписки не переводится и не передается сторонним сервисам.

Используются локальные gettext-каталоги aiogram: 227 сообщений на каждый язык.
Числа, форматные подстановки, HTML и ссылки проверяются автоматически.
Для обновления `.po` и компиляции `.mo`: `python scripts/compile_locales.py`
с dev-зависимостью `Babel==2.17.0`. Внешний переводчик в runtime не используется.
Начальные переводы не проходили независимую вычитку носителями языков.

Финансовые расчеты, Decimal, валюты, ранги, лимиты, сроки и UTC+8 не меняются.
Изменение сохраняется в `I18N_PRODUCTION_FIX.patch`; старый локальный калькулятор
не подменяет production-версию. Миграция только добавляет язык и его ограничение,
таймаут ожидания блокировки 5 секунд. Старые воркеры совместимы с новой схемой.
